# 윷놀이 웹 게임 — 요구사항 명세서 (v0.1)

> v0.1 (2026-08-20): 최초 작성. 마피아42 인게임 윷놀이 미니게임을 웹으로 포팅하는 프로젝트의 첫 요구사항 문서.

## 0. 배경

- **마피아42**라는 게임의 인게임 미니게임 **"윷놀이"**를 웹으로 이식하는 프로젝트. [[project_songpyeon_web_game]]과 같은 계열의 포팅 작업.
- 참고 영상(https://youtube.com/shorts/6ASJPIJF08Y)을 `/watch`로 확인: 팀당 2명(상단 좌/우 팀 박스에 아바타 2개씩), 전통 윷놀이판(호랑이 문양) 위에 윷가락 4개가 던져지는 연출, 하단 채팅창과 말풍선, "조교" 같은 캐릭터 카드 이벤트 등을 확인. 상단에 보이는 숫자(3920, 4615 등)는 마피아42 자체 재화 표시로 추정되며 이번 포팅 범위에서는 제외(§9).

## 1. 게임 구조 개요

- **2팀 × 2인 = 총 4인**이 모이면 시작. 팀 개수/인원 구성은 이번 버전에서는 고정(2팀, 팀당 2명).
- **인당 말 2개**, 즉 팀당 말 4개(2인 × 2개)가 보드에 존재.
- 코인/화폐 시스템 없음 (§9).

## 2. 캐릭터 선택

- 4명의 플레이어는 게임 시작 전 **교주 / 성직 / 마담 / 의사** 중 하나를 선택 (4종 4인, 중복 없이 한 명씩 배정하는 것으로 가정 — 추후 확인 필요, §11).
- **캐릭터별 능력 효과는 이번 문서의 범위 밖.** 선택 화면/배정 로직까지만 이번 포팅에 포함하고, 실제 효과는 별도 브레인스토밍 세션에서 설계.

## 3. 매칭 / 로비 흐름

- songpyeon과 동일한 방식: 로비에서 방을 만들거나 기존 방에 참가. 4명이 모이면 게임 시작.
- 미리 팀을 맞춰서 큐에 들어가는 방식이 아니라, 방 안에서 각자 팀을 선택하는 구조(§2의 캐릭터 선택과 함께 진행되는 대기실 단계로 가정 — 세부 UI는 설계 단계에서 확정).

## 4. 턴 진행 방식

- **개인 턴제.** 4명이 팀을 섞어서 순환한다 — 예: A팀원1 → B팀원1 → A팀원2 → B팀원2 → (다시 A팀원1)처럼 같은 팀이 연속으로 턴을 갖지 않도록 교차 순환.
- 턴을 잡은 플레이어는 **자기 말 2개만** 선택해서 이동할 수 있다 (팀원의 말은 이동 대상이 아님 — v0.1에서 정정된 규칙).
- 윷/모가 나오면 **같은 플레이어가 한 번 더 던진다** (턴이 다음 사람에게 넘어가지 않음).

## 5. 윷 던지기 메커니즘 (게이지)

- 화면을 꾹 눌러서 게이지를 채우는 방식(모두의마블 스타일). 게이지는 시간에 따라 왕복하는 파형이며, 각 결과(빽도/도/개/걸/윷/모)에 대응하는 구간의 너비는 실제 윷 4개 확률 분포를 반영한다(도가 가장 넓고, 모/빽도가 가장 좁음 — 정확한 확률 수치는 설계 단계에서 결정).
- **서버 시간 기반 판정.** 클라이언트는 "누른 시각"과 "뗀 시각"만 서버에 전송하고, 서버는 자신의 시계로 그 시점의 게이지 위치를 재계산해 결과를 확정한다. 클라이언트가 보고하는 게이지 값 자체는 신뢰하지 않는다(서버 권위형 원칙 유지).
- 이 구조는 플레이어의 타이밍 실력이 결과에 실제로 영향을 주는 스킬형 구조이면서도, 서버가 검증 가능해 조작이 불가능하다.

## 6. 말 이동 규칙

전통 한국 윷놀이 규칙을 그대로 따른다.

- 결과별 이동 칸수: 빽도 -1, 도 1, 개 2, 걸 3, 윷 4(+한 번 더 던짐), 모 5(+한 번 더 던짐).
- **지름길**: 보드 모서리에서 대각선 지름길로 진입 가능 (전통 규칙).
- **잡기**: 상대 팀 말이 있는 칸에 도착하면 상대 말은 시작점으로 되돌아간다.
- **업기**: 같은 팀 말끼리는(§4 정정에 따라 실질적으로는 "자신의 말 2개끼리") 업어서 함께 이동할 수 있다.

## 7. 승리 조건

- **팀 내 한 명이라도 자기 말 2개를 모두 완주(판 밖으로 탈출)시키면 그 팀이 승리한다** (v0.1에서 정정 — "팀 전체 말 4개 완주"가 아님).

## 8. 채팅 말풍선

- 채팅을 입력하면 해당 유저의 프로필(아바타) 쪽에 말풍선으로 채팅 내용이 표시되었다가, 잠시 후(기본 가정 3초 — 조정 가능, §11) 자동으로 사라진다.

## 9. 범위 제외

- 화면 상단에 표시되는 코인/포인트 숫자 — 마피아42 자체 재화 표시로 추정, 장식 요소로 간주하고 이번 포팅에서 구현하지 않음.
- 캐릭터(교주/성직/마담/의사) 능력 효과 — 선택 UI까지만 포함, 효과는 별도 설계 예정(§2).

## 10. 기술 스택

- 프론트: React + TypeScript + Vite
- 서버: Node + TypeScript + Colyseus, **서버 권위형** (말 위치, 턴 순서, 윷 던지기 판정 등 핵심 상태는 서버가 소유하고 클라이언트는 렌더링 + 입력 전송만 담당)
- 윷가락이 굴러떨어지는 연출에 **Matter.js**(2D 물리엔진) 적용 — 결과는 §5에 따라 서버가 이미 확정한 값이며, 물리 시뮬레이션은 그 결과를 자연스럽게 보여주기 위한 클라이언트 전용 연출.
- songpyeon 프로젝트([[project_songpyeon_web_game]])와 동일한 스택을 재사용해 리스크를 낮추고, 던지기 연출에서만 새로운 요소(Matter.js)를 시도.

## 11. 열린 질문 / 추후 결정사항

- 캐릭터 4종을 4명이 정확히 한 명씩 나눠 갖는지, 중복 선택이 가능한지 확정 필요.
- 대기실에서 팀 배정이 자동인지 수동 선택인지 확정 필요.
- 채팅 말풍선 노출 시간(기본 가정 3초)의 정확한 값.
- 게이지 구간별 정확한 확률/너비 수치.
- 배포 방식은 미정 (songpyeon/omok 선례를 참고해 추후 결정).
