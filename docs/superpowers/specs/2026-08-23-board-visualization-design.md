# 실제 윷판 시각화 + 캐릭터 표시

> `docs/superpowers/specs/2026-08-22-diagonal-shortcut-model-design.md`가 정확히 모델링해둔 서버 좌표계(`outer`/`shortcutIn`/`center`/`shortcutOut`/`start`/`finished`)를 실제 정사각형 윷판 모양으로 그리고, 말에 캐릭터 그림을 표시하는 후속 스펙. 참고 영상(마피아42 인게임, `https://youtube.com/shorts/6ASJPIJF08Y`)의 레이아웃(네 모서리 플레이어 카드 + 중앙 던지기)을 그대로 재현한다.

## 0. 배경 — 지금 상태

- `GameBoard.tsx`는 실제 윷판 모양이 아니라 외곽 1~19번을 일렬로 나열한 리스트 + 중앙 칸 + 플레이어별 대기/완주 텍스트 트레이다.
- `TurnPanel.tsx`는 별도의 "누르고 있다가 떼서 던지기" 버튼을 갖고 있다.
- 닉네임/로그인 시스템은 없다 — `playerLabel(sessionId, room)`이 `"A팀 나"` / `"B팀 8kN3"` 같은 표시 문자열을 이미 만들어준다. 이번 스펙은 이 함수를 그대로 재사용하고, 실제 로그인/닉네임 도입은 범위 밖(§9)이다.
- 이번 세션에서 브레인스토밍 중 `character.webp`(사용자가 제공한 마피아42 캐릭터 능력 참고 이미지)에서 4종 캐릭터(교주/성직/마담/의사) 초상화를 추출·배경 제거해 `client/src/assets/characters/{gyoju,priest,madam,uisa}.png`로 이미 저장해뒀다 — 이 스펙은 이 파일들을 실제로 화면에 연결하는 작업까지 포함한다.

## 1. 화면 레이아웃

```
┌───────────────────────────────────────┐
│ [카드: 닉네임+말]      [카드: 닉네임+말] │  ← 상단 좌/우
│                                         │
│         ┌─────────────────┐            │
│         │ ●○○○○○○○●        │            │
│         │ ○   ＼   ／   ○  │            │
│         │ ○    ＼／    ○  │            │
│         │ ○  [TurnPanel] ○ │            │
│         │ ○    ／＼    ○  │            │
│         │ ○   ／   ＼   ○  │            │
│         │ ●○○○○○○○●        │            │
│         └─────────────────┘            │
│                                         │
│ [카드: 닉네임+말]      [카드: 닉네임+말] │  ← 하단 좌/우
└───────────────────────────────────────┘
```

- 정사각형 보드가 화면 중앙. 네 모서리에 `PlayerCorner` 카드.
- **2v2(4명)**: 네 모서리 모두 사용, **A팀 = 좌상단·우하단 대각선**, **B팀 = 우상단·좌하단 대각선**으로 고정. 같은 팀 두 명 중 누가 좌상단/우하단인지는 `players`(또는 `turnOrder`) 배열에서 그 팀에 속한 순서(먼저 나오는 사람이 좌상단)로 정한다.
- **1v1(2명)**: 좌상단·우하단 두 모서리만 사용(우상단·좌하단은 비움) — `turnOrder[0]`이 좌상단, `turnOrder[1]`이 우하단.
- `ParticipantBar`(채팅 말풍선)와 `ChatInput`(하단 입력창)은 기존 위치 그대로 — 이번 스펙과 무관.

## 2. `PlayerCorner` — 모서리 플레이어 카드 (신규 컴포넌트)

내용은 딱 두 가지만:

1. **닉네임 텍스트** — `playerLabel(sessionId, room)` 그대로 사용. 새 아바타 아이콘이나 점수/코인 숫자는 넣지 않는다(참고 영상에는 있지만 사용자가 명시적으로 제외 요청).
2. **본인의 "대기 중"인 말만** 한 줄로 — `positionKind === "start"`인 말만 캐릭터 토큰(§3)으로 나열. **완주(`finished`)한 말은 카드에서 그냥 사라진다** — 대기 트레이와 완주 트레이를 한 카드에 같이 보여주면 어떤 게 어떤 상태인지 헷갈린다는 사용자 피드백에 따른 결정. 별도의 완주 표시/트레이는 만들지 않는다.

칸(대각선 배치, 몇 개 쓸지)은 `App.tsx`(또는 이를 대체할 상위 컴포넌트)가 `room.state.mode`와 `players` 순서를 보고 4개 슬롯 중 몇 번째 슬롯에 어느 `sessionId`를 넣을지 계산해서 `PlayerCorner`에 넘긴다 — `PlayerCorner` 자신은 위치 계산 로직을 모르는, 주어진 슬롯에 그리기만 하는 순수 컴포넌트로 유지한다(단일 책임).

## 3. 캐릭터 토큰 — 이미지 · 팀 색 · 업기 표시

**소스 이미지**: `client/src/assets/characters/{gyoju,priest,madam,uisa}.png` — 이미 배경 제거된 파랑 계열 원본. `matchTypes.ts`의 `CHARACTERS = ["교주","성직","마담","의사"]` 문자열과 파일명 매핑은 다음과 같이 고정한다:

| 서버 캐릭터 문자열 | 이미지 파일 |
|---|---|
| `"교주"` | `gyoju.png` |
| `"성직"` | `priest.png` |
| `"마담"` | `madam.png` |
| `"의사"` | `uisa.png` |

**팀 색**: 원본 PNG는 그대로 **1팀(A팀) 색**(파랑)으로 쓴다. **2팀(B팀)**은 옷/두건 색만 빨강으로 바뀐 별도 PNG(`{name}_red.png`, 이미 이번 세션에서 HSV 색조(hue) 변환 스크립트로 미리 생성해 `client/src/assets/characters/`에 정적 파일로 저장해둔 파일 — 런타임에 다시 계산하지 않는다)를 쓴다 — 피부색·머리카락·검정 모자·흰색 장식은 그대로 두고 파란 계열(hue 약 0.42~0.78 범위, 채도 0.15 이상)만 빨강(hue 0)으로 옮기는 변환. 점이나 테두리 색으로 팀을 구분하지 않는다(사용자가 명시적으로 거부) — **캐릭터 옷 색 자체가 팀 표시**다. 컴포넌트는 `owner.team === "A" ? "{name}.png" : "{name}_red.png"`처럼 단순 분기만 하면 된다.

**토큰 렌더링**: 흰 카드/테두리 박스 없이 캐릭터 그림 자체만, `filter: drop-shadow(...)`로 살짝 그림자만 넣어 배경과 분리. 소스 PNG마다 원본 가로세로 비율이 달라서(추출 크롭 결과가 캐릭터별로 다름), 화면에는 모두 같은 높이로 정규화해 표시한다(이미 세션 중 확인된 요구사항 — "크기도 똑같이").

**업기(같은 칸에 여러 말)**: 카드/테두리 없이 캐릭터 그림들을 카드 뭉치처럼 살짝 어긋나게 겹쳐 쌓는다(맨 위 말이 가장 잘 보이고 뒤로 갈수록 조금씩 오프셋). 업기는 서버 규칙상 **소유자(owner) 기준**이므로(팀 기준 아님, `CLAUDE.md` 기존 게이트카) 한 칸에 겹치는 말은 항상 같은 팀 색이다. 1v1은 한 사람이 말 4개를 다 조종하므로 최대 4개까지 겹칠 수 있다 — 겹침 오프셋 간격을 그 정도 개수에서도 맨 위 말 얼굴이 보이도록 작게 잡는다.

## 4. 보드 좌표계 → 실제 렌더링

**모양**: 회전 없는 정사각형(마름모 아님). 한 변에 모서리 2개 + 중간칸 4개.

**전체 20개 외곽 위치**와 서버 인덱스의 대응 (반시계, 오른쪽 아래 모서리=시작/도착):

| 구간 | 서버 index | 물리적 위치 |
|---|---|---|
| 시작 모서리 | `start`(대기/도착) | 오른쪽 아래 꼭짓점 |
| 1~4 | `outer` index 1~4 | 오른쪽 변, 아래→위 |
| 5 | `outer` index 5 (지름길 진입점) | 오른쪽 위 꼭짓점 |
| 6~9 | `outer` index 6~9 | 위쪽 변, 오른쪽→왼쪽 |
| 10 | `outer` index 10 (지름길 진입점) | 왼쪽 위 꼭짓점 |
| 11~14 | `outer` index 11~14 | 왼쪽 변, 위→아래 |
| 15 | `outer` index 15 (지름길 진입점) | 왼쪽 아래 꼭짓점 |
| 16~19 | `outer` index 16~19 | 아래쪽 변, 왼쪽→오른쪽 |

**대각선 지름길**: 4개 모서리(시작 모서리는 진입점 없음, §`diagonal-shortcut-model-design.md` §1 참고) 중 5/10/15번에서 중앙으로 이어지는 대각선. 각 팔은 모서리→중간칸 2개→중앙, 총 3칸:

- `shortcutIn{junction:5|10|15, step:1|2}` → 해당 모서리와 중앙을 잇는 대각선 위의 중간 좌표(step 1은 모서리 쪽에 가깝게, step 2는 중앙 쪽에 가깝게).
- `center` → 정중앙.
- `shortcutOut{step:1|2}` → 중앙에서 **시작/도착 모서리(오른쪽 아래)** 로 이어지는 대각선의 중간 좌표(step 1은 중앙 쪽, step 2는 도착 모서리 쪽). 이 팔은 항상 이 방향 하나뿐이므로 junction 구분이 없다(모델 스펙 §3과 동일 이유).

**좌표 구현 방식**: 위치 종류별로 (x%, y%) 좌표를 계산하는 순수 함수 하나(예: `positionToCoords(kind, index): {x: number, y: number}`, 0~100 퍼센트 값)로 만들고, 보드는 SVG 또는 절대 위치(`position: absolute; left: x%; top: y%`) 레이어로 그린다 — 셀 원(○), 대각선 선(4개), 모서리 강조(●)는 배경으로 고정 그리고, 그 위에 말 토큰을 좌표에 맞게 올린다.

말이 `start`/`finished` 위치인 동안은 보드에 그리지 않는다(§2의 모서리 카드에서 대기 중 표시로 대체, 완주는 아예 사라짐).

## 5. 윷 던지기 인터랙션 (TurnPanel 재구성)

**핵심 변경**: 전용 버튼을 없애고, **보드 영역(정사각형 전체) 자체**를 누르고 있으면 게이지가 차는 대상으로 바꾼다. 화면 전체가 아니라 보드 영역 안에서만 눌러야 반응한다.

- `gaugePhase === "idle"`이고 내 턴이면, 보드 중앙(대각선 X자 안쪽 빈 공간)에 윷가락 4개가 **정지 상태**로 표시된다(기존 `YutSticks.tsx`의 던짐 애니메이션과는 다른, 새로운 "대기 중" 정적 표시 — 같은 4개 막대 이미지를 그냥 나란히 세워두면 된다).
- 보드 영역을 누르면(`pointerdown`) `throwStart`, 떼면(`pointerup`/`pointercancel`) `throwRelease` — 메시지 이름과 서버 판정 로직은 기존과 완전히 동일, 트리거 UI만 바뀐다.
- **포인터 캡처 제약(반드시 지킬 것, `docs/TROUBLESHOOTING.md` #9)**: 캡처 대상 엘리먼트(보드 루트 div)는 `idle`→`charging`→`resolved` 전환 내내 **같은 DOM 노드**로 유지되어야 한다 — `gaugePhase`에 따라 다른 JSX 브랜치로 조건부 렌더링하면 안 되고, 클래스/자식 콘텐츠만 바꾼다. 보드는 게임 내내 항상 마운트돼 있으므로(트레이가 사라지고 보드만 남는 게 아니라 보드 자체가 화면에 계속 있음) 기존 버튼 방식보다 오히려 이 제약을 지키기 쉽다.
- `gaugePhase === "resolved"`가 되면 기존 `YutSticks.tsx`(Matter.js 던짐 애니메이션)가 그대로 재생되고, 이후 흐름(결과 표시, 이동할 말 선택 버튼, 지름길 사용 체크박스)은 `TurnPanel.tsx`의 현재 로직을 그대로 재사용한다 — 이 부분은 로직 변경 없음, 위치만 보드 중앙으로 옮긴다.
- `GaugeBar`(게이지 막대)도 보드 중앙 근처에 계속 표시.

**컴포넌트 책임 분리 제안**:
- `GameBoard.tsx` — 보드 배경(칸/대각선) 그리기 + 말 토큰 배치(§3, §4) + 보드 영역의 pointerdown/up 핸들러(누르기 인터랙션의 소유자가 됨, `throwStart`/`throwRelease` 전송).
- `TurnPanel.tsx` — 턴 표시/남은 시간, `gaugePhase==="idle"`일 때 대기 중 윷가락, `charging`일 때 `GaugeBar`, `resolved`일 때 `YutSticks` + 결과 텍스트 + 말 이동 버튼. `GameBoard`가 렌더링하는 보드의 중앙 좌표 위에 겹쳐서(overlay) 그린다.
- `PlayerCorner.tsx`(신규) — §2.

`App.tsx`는 `playing` 단계에서 이 셋을 정사각형 레이아웃(§1)으로 배치하는 상위 컨테이너 역할만 한다(CSS Grid 9분할: 네 모서리 + 중앙 보드).

## 6. 테스트 전략

client에는 자동화 테스트 프레임워크가 없다(기존 관례, `CLAUDE.md`). 검증은:

- `npm run build`(client) — 타입체크 통과 확인.
- 실제 브라우저에서 2개 이상 탭으로 접속해 2v2/1v1 각각 플레이 — 특히 **포인터를 누른 채로 오래 유지했다가 뗐을 때 매번 `throwRelease`가 정상 전송되는지**(TROUBLESHOOTING #9 재발 여부)를 여러 번 반복 확인. 보드 영역 밖에서 누르기 시작했을 때는 반응하지 않는지도 확인.
- 업기 시각 확인: 같은 소유자의 말 3~4개가 한 칸에 겹쳤을 때 안 겹쳐서 화면 밖으로 나가거나 서로 완전히 가려서 몇 개인지 안 보이는 경우가 없는지.
- 팀 색 확인: A팀/B팀 각각 캐릭터 4종 전부 파랑/빨강으로 올바르게 나오는지.

## 7. 이번 범위에서 제외하는 것

- 로그인/닉네임 시스템 도입 — `playerLabel` 그대로 사용, 실제 닉네임 기능은 별도 후속 작업(§0 참고, 사용자가 이번 세션에서 "로그인은 나중에" 확정).
- 관전자 모드, 방 목록/방 만들기 로비 — 별도 진행 예정 기능(이번 스펙과 독립).
- 원형 아바타 아이콘, 코인/점수 표시 — 참고 영상에는 있지만 이번 스펙에서 명시적으로 제외.
- 서버 좌표 모델 자체의 변경 — 이미 완료된 `2026-08-22-diagonal-shortcut-model-design.md`를 그대로 씀, 이번 스펙은 순수 시각화 레이어.
